# 技术分析：MH4G / MH4U 盾斧快速变形斩 GP

本文描述最终 ExeFS v3 的已验证结构、推断边界和仍未解决的问题。它是从研究档案中提炼出的公开技术说明，不复述所有失败实验。

AI 生成的逆向工作与人工操作的运行时验证之间如何分工，详见[开发方式与贡献分工说明](DEVELOPMENT_METHODOLOGY.zh-CN.md)。

范围说明：机制重建、motion 序列和 v6 状态机细节以 **MH4G v1.2 汉化版**为基础。第 4、6 节会把这些结果与已经独立重定位、动态验收的 MH4U USA／EUR v1.1 明确区分。三个目标版本共享游戏层动作身份，但可执行地址、分支编码、code cave、overlay 与 IPS 记录均属于各自版本，不能互换。

## 1. 问题不是一个独立的“GP 开关”

玩家看到的是一招快速变形斩，但程序中的行为分散在多个层级：

```text
输入与摇杆状态
→ 动作入口参数
→ Action 分流
→ motion / phase 提交
→ 资源对象与生命周期
→ Guard / 碰撞结果
→ 红盾瓶爆与后续派生
```

早期对单个字段、结果脚本、碰撞记录和通用 flag 的大量测试均未得到可独立移植的 GP 开关。最终有效方案依赖普通变形逻辑、快速可见资源以及可靠生命周期回收的组合。

### 1.1 Azahar 2126.0 是动态方法成立的前提

这套结论不只来自静态反汇编。关键因果证据需要在同一运行会话中完成动作采样、有限日志记录、机器码安装、逐字读回、行为测试、状态复查和必要时恢复原代码。这要求 GDB 连接能够长时间保持可读、可写并允许重复暂停／继续。

此前 Azahar 版本无法稳定维持 GDB 连接，远程会话会出现中断、读写失败或无法继续复用的情况。在这种条件下，单次补丁现象无法与安装是否成功、代码是否实际执行、JIT 缓存或连接故障可靠区分，也无法保证失败实验后的安全恢复。因此 **Azahar 2126.0 是本项目能够立项并形成可重复动态验证闭环的已验证调试基线**，而不只是一个偶然使用的模拟器版本。

需要进一步区分“GDB 连接可用”和“传统断点调试可用”。Azahar 2126.0 解决了持续连接与客体内存读写的基础问题，但传统交互式 breakpoint／watchpoint 仍不适合作为主要证据采集方式：断点可能伴随远程 `E01` 等错误，继续后会话可能失去可用性；watchpoint 会对同址同值写入产生噪声触发，也可能在高频状态更新中不断停止。由此得到的单次现场不能直接当作动作路径或 GP 边界证据。

项目最终采用的是**脚本化插桩与可恢复实验**：

- GDB preflight／enable／status／disable 脚本负责安装前基线检查、机器码写入、逐字读回、状态检查和安全恢复；
- 临时代码 hook 与低噪音有限 logger 把 Action、motion ID、游标、来源和前缀序列写入预先分配的日志区；
- 内存快照、分块代码导出与离线 SQLite／反汇编分析负责大范围搜索和严格差分；
- 游戏内成功防御、红盾瓶爆、动画身份、派生和状态回收负责最终因果验收。

少量固定代码点的窄断点或字面地址 watchpoint 曾用于验证诊断工具本身或缩小候选范围，但项目没有把它们作为可持续的主采集路线；所有关键结论最终都要求脚本化记录、机器码读回和游戏内行为相互闭合。

该要求属于研究复现条件。正式 v3 由 ExeFS 自动加载且正常使用不需要 GDB，所以现有证据不能把 2126.0 直接宣布为最终模组面向玩家的最低运行版本。

## 2. 已确认的动作身份

| 动作 | Action |
| --- | --- |
| 无摇杆输入的快速变形斩 | `000B0400` |
| 无摇杆输入的普通变形斩 | `00060400` |
| 摇杆输入的快速变形斩 | `001C0400` |
| 摇杆输入的普通变形斩 | `001B0400` |

MH4G v1.2 在 `00CA82D4..00CA8313` 具有四个同构入口。进入共同主体 `00CAC2D4` 前，两个参数轴分别选择无摇杆输入／摇杆输入与普通／快速：

| 入口 | `(r2,r1)` | 含义 |
| --- | --- | --- |
| `00CA82D4` | `(0,0)` | 无摇杆输入普通 |
| `00CA82E4` | `(0,1)` | 无摇杆输入快速 |
| `00CA82F4` | `(1,0)` | 摇杆输入普通 |
| `00CA8304` | `(1,1)` | 摇杆输入快速 |

旧版本只覆盖无摇杆输入的快速入口，因此推动摇杆时会进入未覆盖的 `(1,1)` 分支。这是旧版“有时快速 GP 失败”的主要结构性解释。

该结论由两套有限运行时记录器交叉验证。在 Action logger 中，摇杆输入快速变形捕获到 `001C0400`，“剑 X→摇杆输入普通变形”路径捕获到 `00040400 → 001B0400`。在同一 motion logger 与四-hook 补丁安装下，已经被覆盖的无摇杆输入快速阳性对照记录到 `592 → 583`，而尚未打第五 hook 的摇杆输入快速路径没有进入既有 native wrapper，日志为零。因此该零结果具有同安装阳性对照，证明分支绕过旧补丁提交路径，而不是记录器随机失效。

## 3. `0x592` 与 `0x583`

无摇杆输入动作的低噪音运行时记录得到：

```text
普通变形：592 → 583
原生快速：583
```

这证明 `0x592` 是普通逻辑与原生快速路径之间可观察到的关键差分，但不能把它简单命名为“GP 函数”或“GP flag”。本补丁重建与普通变形相关的 `0x592` motion／资源生命周期，同时保留快速可见资源；该组合足以让现有游戏系统产生 GP 与红盾瓶爆。

但这并没有把 `0x592` 本身隔离成 GP 的直接因果开关。尚未定位的消费者可能依赖该上下文进入的某项资源、phase／事件变化，或下游 Guard／碰撞条件。因此目前证明的是足以完成本盾斧补丁的关系，而不是 `0x592` 在其他动作或武器中具有通用 GP 语义。

## 4. 最终补丁结构

MH4G v1.2 汉化版的正式 v3 由五个 hook 和一段 640-byte overlay 组成：

| 角色 | 地址 | 原指令 | 补丁指令 |
| --- | --- | --- | --- |
| 资源 overlay | `00941334` | `E92D5FF0` | `EA12326B` |
| native motion wrapper | `00B0D0A0` | `EBFFA103` | `EB0B0340` |
| 无摇杆输入快速入口 | `00CA82EC` | `E3A01001` | `EA0496BC` |
| 摇杆输入快速入口 | `00CA830C` | `E1A01002` | `EA0496B4` |
| 动作结束 wrapper | `00CAC478` | `EBF96833` | `EB048661` |

运行时 overlay 位于 `00DCDCE8..00DCDF67`，共 640 bytes／160 words。v3 新增的只是摇杆输入快速入口 hook；overlay 本身与已完成综合动态验收的 v6 机器码逐字节相同。

高层行为如下：

```text
无摇杆输入或摇杆输入的快速入口
→ 清理旧状态并设置 fast marker
→ 保留无摇杆输入/摇杆输入轴，改走对应普通变形逻辑
→ motion 提交时临时建立快速可见资源上下文
→ 现有 Guard/碰撞系统产生 GP，红盾系统自然追加瓶爆
→ native motion 前缀与动作结束路径恢复资源和内部状态
```

这不是永久把快速 Action 改成普通 Action，也不是全局替换普通变形资源。补丁的核心是把逻辑与可见资源在有限生命周期内组合，再在动作边界回收。

### 4.1 MH4U 的独立重定位

USA 与 EUR 正式版复用了已经验收的行为设计和 640-byte 布局，但两个可执行文件都从各自运行时镜像独立定位。所有 hook 与外部分支均按目标地址重新编码；它们都不是只修改 MH4G IPS 的 Title ID 或文件名得到的包。

| 目标版本 | Title ID | 五个运行时 hook | Overlay 范围 |

## 5. v6 前缀状态机为什么必要

早期 overlay 能产生快速动画和 GP，但在连续使用或普通动作回归时出现过状态残留与动画污染。关键运行时序列为：

```text
A：正常快速        592 → 583
B：快速 GP 后派生  592 → 592 → 583 → 579 → 56B
C：后续普通动作    567 → 592
```

v6 在资源尚未实际切换时，把第五个状态字临时复用为前缀阶段：

- 看到 `592` 时保留 marker 并记录前缀阶段；
- 前面已有 `592` 时允许后续 `583` 继续；
- 看到其他 motion，或未见 `592` 就出现 `583` 时，先恢复五个状态字再透传；
- overlay 真正建立后，第五字恢复为真实的资源长度保存字段，不与前缀阶段重叠。

因此快速链可以连续重入，而普通动作的 `567` 前缀会在普通 `592` 之前清理 dormant marker，避免普通动画被快速资源污染。

## 6. 验证范围

最终结论同时依赖离线验证与动态验证：

- IPS 反向解析、记录偏移、little-endian payload 和分支目标检查；
- 640-byte overlay 尺寸、关键签名与 SHA-256；
- 完整重启后由 Azahar 自动加载，而非依赖 GDB 注入；
- 五 hook、overlay、`592/583` literal 与状态字读回；
- 无摇杆输入／摇杆输入、普通／快速动画隔离；
- GP、红盾瓶爆、连续摇杆输入快速 GP；
- 斧下砸、回旋斩、大解等主要派生；
- 动作结束、重复进入、翻滚、换区和状态回收；
- CPU JIT 开启后的长时间实战。

最终状态允许全零，或曾被单独验证为安全且可由后续入口回收的 dormant marker。天然 `1,0,0,0,0` 状态已经直接接续普通变形进行过污染测试，普通动画保持正常；后续正式验收会话也取得过五字完整归零。

三个区域版本均有各自的运行时验收，不是从 MH4G 结果直接外推：

| 目标版本 | 独立动态验收 |
| --- | --- |
| MH4G Japanese／汉化 v1.2 | ExeFS 干净启动自动加载、五 hook 读回、无摇杆输入／摇杆输入与普通／快速隔离、连续 GP 和主要派生通过；另完成约 10 分钟 CPU JIT 开启的摇杆输入实战，最终验收状态五字全零。 |
| MH4U USA v1.1 | CPU JIT 开启下干净启动自动加载及约 22 分钟混合回归通过，覆盖分支切换、连续 GP、瓶爆、主要派生、翻滚、换区和战斗恢复；最终五字全零，已验收 RC1 IPS 原样升为正式版。 |
| MH4U EUR v1.1 | 先以 CPU JIT 关闭的 GDB 候选通过核心分支并安全恢复，再完成 ExeFS 干净启动自动加载与约 10 分钟 CPU JIT 开启混合回归；最终五字全零，已验收 RC1 IPS 原样升为正式版。 |

## 7. 快速 GP 窗口的最终结论

曾经计划人工裁剪快速 GP 尾端，但该任务已经取消。无摇杆输入快速变形斩的自然测量中，最晚可信阳性为精确 `27.0` 帧；最早可信接触阴性约为 `30.006` 帧，并在约 `30.008` 帧独立复现，28～29 帧仍未分类。既有普通变形参考为 `32.5` 帧阳性、`33.0` 帧阴性，因此当前快速窗口已经可以确认更短。

用户随后与 MHGU 对比还确认：官方摇杆输入的快速变形斩本身也有 GP，而且其尾端窗口体感与当前 MH4G v3 接近。该 MHGU 结论属于实际游玩对比，不是跨游戏逐帧测量。

可以确认：快速窗口不是简单完整继承普通窗口。

强推断：原生动作生命周期、phase 或 motion 变化会自然终止 GP。

尚未证明：由某个特定 Action、单一 flag 或已经定位的固定条件关闭 GP。研究中还发现“从动作 0 帧直接跳到目标帧再冻结”的方法会跳过自然事件，因此其晚帧阳性不能作为自然窗口证据；公开结论不采用这些失效样本。

此前“快速起手天然存在 GP 空窗”的怀疑也应继续降级，而不能写成既定事实。第五 hook 之前，摇杆输入会完全绕过已补丁路径，足以更好地解释旧版可复现失败。朝向不正或输入时机错误仍会造成正常防御失败，但本项目没有证明另有一个固定的原生起手空窗。

## 8. 证据等级

### 已验证

- 四个动作身份与摇杆输入分支结构；
- 五 hook 与 640-byte overlay 的最终机器结构；
- 普通／快速视觉隔离、GP、瓶爆、主要派生和状态回收；
- 摇杆输入分支未覆盖是旧版失败的主要解释；
- 快速窗口并非完整复制普通窗口。

### 强推断

- GP 由重建的 `0x592` 相关 motion／资源上下文进入现有 Guard／碰撞系统后自然形成；
- 快速窗口由后续生命周期、phase 或 motion 变化自然终止。

### 开放问题

- GP 精确关闭条件及其消费者；
- `0x592` 与通用 Guard／碰撞系统之间的完整因果链；
- 是否能把该机制抽象成适用于其他武器的安全通用 GP 移植方法。

这些开放问题不影响 MH4G Japanese／汉化、MH4U USA 与 MH4U EUR 三个 v3 正式版的完成状态。

# MH4G / MH4U 盾斧项目——开发方式与贡献分工说明

[English version](DEVELOPMENT_METHODOLOGY.md)

## AI 辅助逆向工程与人工动态验证

本项目采用的是 **AI 辅助逆向分析和实现 + 人工操作的动态实验与游戏内验收**。它既不应被描述成“完全由 AI 自动制作”，也不应被描述成“没有使用 AI、完全由个人独立完成逆向”。

### ChatGPT / Codex（OpenAI）

ChatGPT 与 Codex 承担了本项目的代码分析和实现工作，主要包括：

- 分析研究过程中提供的 MH4G / MH4U 反汇编、运行时 dump、内存读回、日志、截图和测试报告；
- 建立 Action → 入口参数 → motion／phase → 资源生命周期 → Guard／碰撞的分层模型；
- 提出机制假设、受控对照、失败判据和安全实验顺序；
- 设计 GDB preflight／enable／status／disable 流程、临时 hook、有限 logger、内存导出方案和读回检查；
- 生成本项目自制的逆向脚本、ARM hook／overlay 机器码设计、IPS 构建器、验证器和发布封装逻辑；
- 完成分支解码、MH4U USA／EUR 重定位、code cave 与 IPS 记录检查，以及返回数据的解释；
- 草拟和整理公开 README、Technical Analysis、Research History、Porting Notes、发布元数据与档案结构。

简而言之，本项目自行开发的逆向代码和补丁实现均由 ChatGPT／Codex 在协作过程中生成。AI 并没有亲自操作 Azahar、直接连接正在运行的游戏进程、按下游戏输入，也没有直接看到最终动画和实战现象。

### 项目作者与测试执行者

项目作者承担了运行时研究和实证验收工作，主要包括：

- 提供并维护实际的 MH4G / MH4U、Azahar、GDB、Ghidra 与本地文件环境；
- 提供盾斧实战经验，确定希望实现的游戏行为和有价值的对照场景；
- 在真实模拟器进程中执行每一条 GDB 命令和项目脚本；
- 按安全要求安装、启用、停用、重启和切换实验补丁及 ExeFS 版本；
- 实际执行无摇杆输入／摇杆输入、普通／快速、红盾、GP、连续使用、主要派生、翻滚和换区等测试；
- 采集运行时 dump、内存数值、日志、截图、校验值和游戏内可见结果，再把结果反馈给 AI 分析；
- 识别并排除朝向错误、接触时机错误、动作序列污染、连接故障以及 EUR 标题画面测试等无效样本；
- 将最终结果与 MHGU 对比，决定验收标准和项目范围，并完成 JPN／USA／EUR 三个正式版的最终实机验收。

因此，本项目的逆向结论不是只根据 AI 的静态推断直接成立。关键结论必须由脚本输出、机器码读回、可重复受控测试和人工在实际运行游戏中观察到的行为相互闭合。

## 证据与复现边界

本项目中的 AI 输出属于分析与实现贡献，不能替代运行时证据。机制假设、地址映射、分支编码或补丁设计，在通过对应阶段的检查前都只能视为候选。根据研究阶段不同，这些检查包括原指令 preflight、完整安装代码读回、安全恢复、阳性／阴性对照、可重复游戏内行为、CPU JIT 开启回归、确定性构建和压缩包校验值验证。

反过来，单独一次游戏现象也不会自动被当成机制证明。如果动作路径、接触时机、连接状态、进程状态或插桩有效性无法确认，项目会把该样本作废或降低证据等级。

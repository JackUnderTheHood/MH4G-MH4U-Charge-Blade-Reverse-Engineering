# MH4G / MH4U 盾斧 GP 逆向工程

[English](README.md) · [下载正式补丁](https://github.com/JackUnderTheHood/MH4G-MH4U-Charge-Blade-Reverse-Engineering-/releases) · [技术分析](docs/TECHNICAL_ANALYSIS.zh-CN.md) · [校验值](ARTIFACTS.zh-CN.md)

本项目记录《怪物猎人4G / 4 Ultimate》盾斧 GP（Guard Point）与红盾瓶爆机制的逆向过程，并提供两组已经完成实机验证的 Azahar ExeFS 补丁。

项目最初只是想让快速变形斩获得 GP。研究继续深入后，我们进一步拆开了四个容易混在一起的问题：

1. 动作进行到什么时候，GP 才能真正挡住攻击；
2. 防御是否真的成立，而不只是出现防御火光；
3. GP 如何提高防御性能并改变后退等级；
4. 红盾瓶爆如何从成功接触一路进入碰撞和伤害结算。

最终成果不再依赖 v3 的动作身份替换。v4 保留快速变形斩原本的动作身份与动画，只在游戏已经存在的原生时序上补齐 GP 状态，并在成功接触后按红盾条件进入原生瓶爆链。

## GP 与红盾瓶爆机制图

![GP 与红盾瓶爆机制流程图](assets/gp-phial-burst-flowchart.svg)

这张图把三个容易混在一起的机制分开表示：

- `state+F0 bit 0x10` 是防御真正成立所需的关键条件。只看到防御火光，并不能证明攻击已经被挡住。
- `state+F0 bit 0x2000` 不会单独让 GP 防御判定生效。它只在防御已经成立后，把内部后退判定值减少 10，最低保持为 1。
- 成功接触也不会无条件产生瓶爆。没有红盾时只完成防御；红盾有效时，经过验证的路径才会继续进入原生瓶爆对象、碰撞处理、结果队列和最终 HP 伤害。

机制图用于快速理解整体关系，不代替完整证据链。具体调用点、Action 过滤，以及快速变形斩和剑模式蓄力斩采用的不同瓶爆接入方式，见[技术分析](docs/TECHNICAL_ANALYSIS.zh-CN.md)。

## 应该下载哪个版本？

本项目提供两种功能包，**二选一安装**：

### 快速变形斩 GP v4

适合只想修改快速变形斩的玩家。

- 不推动左摇杆和推动左摇杆的快速变形斩都获得 GP；
- 无红盾时可以 GP，但不会产生瓶爆；
- 红盾时成功 GP 会产生一次瓶爆；
- GP 后可以派生大解或斧下砸；
- 不包含剑模式蓄力斩 GP。

### 剑模式蓄力斩 GP v1（合并版）

适合希望同时使用两项功能的玩家。

- **已经完整包含快速变形斩 GP v4**；
- 额外让剑模式架盾蓄力阶段获得 GP；
- 小后退和中后退不会打断蓄力，动作可以继续释放；
- 大后退仍按游戏原本的规则打断蓄力；
- 无红盾时不产生瓶爆，红盾时成功 GP 产生一次瓶爆。

不要同时安装两种包。合并版已经包含快速变形斩 GP v4，再叠加独立版会让两个 `code.ips` 发生冲突。

## 安装方法

1. 完全关闭 Azahar。
2. 确认下载的压缩包与游戏地区和版本完全一致。
3. 把压缩包中的 `load` 文件夹合并到 Azahar 用户目录。
4. 确认最终文件位于：

   ```text
   load/mods/<Title ID>/exefs/code.ips
   ```

5. 重新启动游戏，并从正常游戏存档进入。

Windows 默认 Azahar 用户目录通常为：

```text
C:\Users\<用户名>\AppData\Roaming\Azahar
```

## 重要注意事项

- 同一 Title ID 下只能有一个最终生效的 `code.ips`。
- 如果已经安装其他 ExeFS 补丁，请先备份并正确合并 IPS 记录；不要直接覆盖后假定两者能够同时工作。
- 不要同时启用旧版补丁、GDB 测试补丁或研究阶段的实验金手指。
- 开启、关闭或更换补丁前必须完全退出 Azahar。
- 不要读取跨越补丁启用状态创建的即时存档；即时存档可能把旧代码内存一起恢复。
- 本补丁不修改 ROM，也不修改正常游戏存档。

卸载时，完全关闭 Azahar，移走或重命名对应 Title ID 目录中的 `code.ips`，再重新启动游戏。

## 已验证行为

- 快速变形斩两种输入分支的动画均正常且只播放一次；
- 无红盾和红盾条件下的 GP／瓶爆分流正确；
- 每次已测试的红盾 GP 只产生一次瓶爆；
- 快速 GP 后的大解和斧下砸派生正常；
- 普通变形斩、普通 GP 和长按 R 防御没有被污染；
- 蓄力很短、适中释放和持续按住自动释放保持正常；
- 蓄力 GP 的小／中后退继续蓄力，大后退正常打断；
- 三个地区版本都完成了安装读回、状态检查和安全恢复。

怪物多段攻击没有做专项覆盖。现有测试没有观察到重复瓶爆，但这不等于已经穷尽所有多段攻击情况。

## v4 相比 v3 改了什么？

v3 通过五个 hook 和一段 640-byte overlay，让快速动作借用已有 GP 动作的逻辑身份，同时保留快速动画。这个方案完成了功能验证，也帮助研究定位了关键差异，但需要同时管理动作身份和资源生命周期，结构较复杂。

v4 建立在后续机制研究之上：

- 不再替换 motion／动作身份；
- 不再需要五-hook 资源 overlay；
- 快速变形斩独立版只使用两个 hook 和 264-byte code cave；
- 合并版使用三个 hook 和 792-byte code cave；
- GP、后退和瓶爆分别接入已经验证的原生处理链。

因此 v4 不只是版本号变化，而是实现方式已经从“借用动作身份”改成“使用原生 GP 时序”。

完整的前因后果可以概括为：

```text
v3 首先完成五-hook 可用方案
→ v3 成为后续严格对照实验的稳定 A 组基线
→ A/B 实验把防御成立、后退修正和瓶爆提交逐层拆开
→ 在快速动作自身找到原生 mask-2 时序
→ 最终 v4 用两-hook 原生时序实现取代动作身份借用
→ 剑模式蓄力斩 GP 再次复用这些独立机制，成为交叉验证
```

所以 v3 不是应该被抹去的“错误版本”，而是让 v4 能够继续收缩机制并改写实现方式的前提。曾经撤回的“v4 重封装候选”和最终真正的 v4，也已经在[研究历程](docs/RESEARCH_HISTORY.zh-CN.md)中明确分开。

## 技术结论概览

- `state+F0 bit 0x10`：普通防御和 GP 共用的关键条件之一。实验中临时隐藏该位后，防御火光仍会出现，但攻击无法真正被挡住，猎人会被击飞。
- `state+F0 bit 0x2000`：GP 防御性能修正。它不能单独建立防御，而是在防御已经成立时，把内部后退判定值减少 10，最低为 1。
- `B0E5B0`：根据内部判定值选择小／中／大后退。
- `B23B48`：选择相应的后退位移。
- `state+0x489 bit 2`：快速变形斩在红盾成功 GP 后进入瓶爆消费链的条件之一。
- 瓶爆不是单纯视觉特效；项目已经追踪到对象、碰撞、实体解析、结果队列和最终 HP 扣减。

更完整的解释见[技术分析](docs/TECHNICAL_ANALYSIS.zh-CN.md)。如果希望了解研究如何从 v3 走到 v4，请阅读[研究历程](docs/RESEARCH_HISTORY.zh-CN.md)。

## 研究环境

Azahar 2126.0 是本项目已经验证的动态研究基线。更早版本无法稳定维持 GDB 连接；即使在 2126.0 上，传统断点（breakpoint）和监视点（watchpoint）也不能承担主要采集工作。因此项目主要使用自动化 GDB 脚本、临时代码 hook、有限日志记录器（logger）、内存导出和逐字读回完成证据采集。

正式 ExeFS 补丁不需要 GDB。研究环境要求不能直接解释为普通玩家运行补丁的最低 Azahar 版本。
